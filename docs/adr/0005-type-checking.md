# Type checking runs through `astro check`, under the repo-wide tsconfig

Every workspace package exposes a `tsc` script and CI runs them all with a single recursive `pnpm tsc`. `apps/web` was the one package without that script, so the app — the largest body of code in the repo, and the only one containing `.astro` files — was silently skipped by the type-check step while CI reported green. Adding `@astrojs/check` and wiring it as web's `tsc` closes that hole and immediately surfaced two live type errors that had passed review.

Plain `tsc` cannot do this job: it does not parse `.astro`, so a component's frontmatter and its `Props` contract are invisible to it. `astro check` runs the same compiler through the Astro language server, which is why the script is named `tsc` despite not being the `tsc` binary — the name states the role the script plays in the recursive run, and a package whose type-check step is called something else drops out of `pnpm tsc` unnoticed. That is the exact failure being fixed.

`apps/web/tsconfig.json` extends **both** the repo root config and `astro/tsconfigs/strict`, in that order. Astro's preset is second so it wins every shared key (`moduleResolution`, `jsx`, `allowJs`, `verbatimModuleSyntax`, the `${configDir}`-relative `include`/`exclude`), while the root's five extra flags — `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `erasableSyntaxOnly` — survive untouched because Astro's preset sets none of them. Before this, web extended only the Astro preset and was the laxest package in the repo; adding the root flags produced zero new diagnostics, so the divergence was costing strictness and buying nothing.

## Consequences

- **The `tsc` script generates types before it checks them.** `apps/web/tsconfig.json` includes `worker-configuration.d.ts`, which is `wrangler types` output and is now gitignored like every other generated file here. Left ungenerated it would exist locally and be absent in CI — the precise local-green/CI-red asymmetry a type checker exists to prevent. `wrangler types` needs no Cloudflare credentials and makes no network calls, so prepending it to the script is safe in CI. `astro check` regenerates `.astro/` itself via an implicit `astro sync`.
- **No `dotenvx` wrapper, unlike every other web script.** `astro check` only produces diagnostics; it never evaluates the `astro:env` schema's values, so the required `SANITY_STUDIO_*` variables are not needed. Wrapping it would imply a dependency that does not exist.
- **`packages/ui` is still checked by nothing.** Its ten `.astro` UI Components have a tsconfig but no `tsc` script, and web's check cannot cover them: the `include` is scoped to `apps/web/**/*`, so an imported UI Component contributes its `Props` types while bugs inside its body go unreported. Closing this needs `@astrojs/check` plus a minimal `astro.config.mjs` in the package, since `astro check` requires an Astro project root. Deliberately deferred, and the gap is invisible from a green CI run — which is how it survived this long.
- **Warnings and hints do not fail the build.** `astro check` exits non-zero on errors only (`--minimumFailingSeverity` defaults to `error`). One standing hint is expected: `allowJs` pulls `eslint.config.js` into the program, and the `eslint-config` workspace package ships no declarations. It is a true statement about untyped config, and muting it would mean re-adding an `exclude` block whose main effect is a chance to forget `dist`.
- **The tsconfig is two lines.** Everything the old file declared — `strict`, the `include` list, `exclude: ["dist"]` — was already supplied by the Astro preset. Re-stating inherited defaults hides which settings are actually deliberate.
